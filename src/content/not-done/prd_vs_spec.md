PRD (Produc Requirement Document)

- É o documento que define O QUE deve ser construído e POR QUÊ.
- PRD transforma uma ideia em algo claro o suficiente para ser construído
- PRD é por funcionalidade, não por produto
- Documento de alto nível, sem detalhes técnicos e arquiteturais
- Estrutura básica de um PRD
- 1. Problema: O que existe hoje que não deveria, ou o que não existe que deveria.
- 2. Público-alvo: quem tem esse problema e em que contexto
- 3. Solução proposta: o que será construído, sem entrar em como
- 4. Fora do escopo: o que explicitamente não será feito nessa versão
- 5. Critérios de sucesso: Como saberemos que funcionou (pode ser qualitativo aqui)
- 6. Regras e restrições: regras de negócio importantes que precisam ser respeitadas
- Papel do PRD na Engenharia Agência
- No SDD, o PRD é o ponto de partida
- PRD -> SPEC -> TASKS -> Execução -> Validação
- O PRD:
- Define a intenção
- Dá contexto para a IA
- Evita decisões erradas
- Serve como fonte de verdade

- Se o PRD está ruim, a IA não erra... ela só segue um direcionamento ruim com perfeição
- PRD vs SPEC
- PRD: Alto nível, Produto, Intenção, Problema, O QUÊ e POR QUÊ
- SPEC: Baixo nível, Execução, Tasks, Passos concretos, COMO
- Analogia: PRD é o destino (o que queremos construir), e o SPEC é o mapa (como vamos
  chegar lá)
- Na engenharia agência, você não começa pelo código. Você começa pelo CONTEXTO
- O que não estiver no PRD... a IA vai inventar
